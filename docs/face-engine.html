01

一张脸只有两个元素

BLOB + EYE HOLES

BLOB身体 = 193 点多边形

一个近似圆的封闭多边形（顶点数据烘焙在 grok_face_data.h）。 每帧被「平移 → 旋转 → 挤压」三变换摆出姿态 —— 挤压(squash)是弹性感的全部来源： 横向变宽时纵向等比变窄，面积守恒。

HOLE眼睛 = 镂空

眼睛不是"画上去的白块"，而是从身体上挖掉的洞—— 直接露出页面背景色。25 组 48 顶点眼形多边形按 3D 矩阵投影摆放， 所以换眼形、眨眼、视线偏移都只是换一组顶点坐标。

INK墨水 = 垂直渐变

填充色是顶亮底暗的橙渐变（#FF9E2C → ×0.76），模拟受光。 画布清屏色 = 页面底色 #101418，且无边框 —— 脸"悬浮"在界面里，看不出画布边界。

02

一帧的流水线

33ms · VENDOR → CANVAS → FB
1 · POSE

姿态弹簧层

16 个弹簧同时积分：squash / spin / tx / ty / blink / eyeScale / morph… 加上眨眼队列（14% 概率双眨）、视线游走、idle 16 形轮播（3~5s 随机换形，16% 转圈 / 18% 粒子 / 24% 轻声点缀）。 此阶段所有几何量都在 vendor 坐标系（中心 ≈115、半径 ≈114）里算。

2 · TRANSFORM

视口变换 gf_view_to_ss()

canvas = (v − 114.27) × VIEW_K + 200，VIEW_K = (400−28)/230 —— 脸直径 372 钉满画布、中心钉在画布中心。坐标再 ×2 进入 800×800 超采样空间。 想让脸更大？改一个宏，整条链自动跟着缩放（FX 半径同样由 VIEW_K 派生）。

3 · RASTER

软件光栅（不走 LVGL 绘制管线）

多边形扫描线填充进 coverage 位图：身体 set=1、眼睛 set=0（挖洞）； listen 呼吸环等 overlay 直接同缓冲直画。降采样 2×2 coverage 做 AA， 按覆盖率把橙墨水混进底色，写入 ARGB 像素缓冲 expr_buf。

4 · PRESENT

LVGL 画布 → 屏幕

缓冲挂 lv_canvas，invalidate 后由 LVGL flush 做旋转 blit （fbdev 物理竖向 480×800 → 逻辑横向 800×480），写入 /dev/fb0。 LVGL 全程只做"搬运"，不参与表情数学。

03

为什么是弹簧，不是补间动画

x″ = (target−x)·f² − 2ζ√f·x′
动作弹簧参数 [freq, damp]手感
转一圈 spinTurn[6.2, 1.0] 目标 ±2π干脆的整圈旋转，到位即停
换形 morph[9, 1.0] 切 16 眼形快速弹过去，眼形"啪"地切换
眨眼 blink目标先压 0.05 再回 1下落快、回升带一点回弹
呼吸 squash正弦驱动 ±3.5%待机时一直"活着"的微动

所有动作都是同一套二阶弹簧积分的连续量 —— 没有关键帧表、没有缓动函数库。 参数表还原自原版 Grok Bot 表情（geometry 归 xAI，个人学习用途）， 改一个数字就能调"性格"：顶上的滑杆就是 Live 实验。

06

几个反直觉的决定

WHY

why不用 LVGL 画脸

任意多边形挖洞 + 逐像素墨水渐变 + 2×AA，widget 管线表达不了； 直接写 ARGB 缓冲的光栅实现反而最简单，LVGL 只提供画布与上屏。

why几何留在 vendor 坐标系

数学层与分辨率彻底解耦：VIEW_K 一个缩放系数决定脸多大， 换画布尺寸（300→340→400）引擎代码零改动 —— 只踩过一次 overlay 半径忘了派生的坑。

why编译期烘焙数据

193+25×48 个顶点做成 const 数组进 .rodata：无文件 IO、无解析器、 无内存分配，冷启动即渲染，也方便 md5 锁定版本。

why清屏色 = 页面底色

画布自带深色背景 + 边框时会看出"一块贴上去的屏幕区域"。 让引擎清屏色与页面完全一致并去掉边框，脸才真正"长"在界面里。
